# Wasm 最小链路实测

本文保留 2026-10-17 的 `taiyin_probe` 测量口径。后续 `taiyin_web` 的 Dart
接口、日月食／八字／紫微支持与测试结果见 [README.md](README.md#dart-web-初步适配)；
下面的体积、速度不代表扩展后的 Web 目标。

2026-10-17，内核基线 `7c80645e`，实验分支 `codex/wasm-minimal-runtime`。
这里只增加独立实验目录，没有修改生产算法、原生公开接口或 Dart/Python 绑定。

结论：现有 C++ 内核可直接编译成单线程 Wasm，复用原有 OPM2 解析器和路由。
二进制和 Base64 输入均已跑通；不需要定义新星历格式。后续可以在 Dart Web
适配层复用它，而不是维护第二套天文算法；本实验还不是 Dart Web 支持的交付。

## 环境与体积

- Apple M5，macOS / arm64（Darwin 27.0.0）。
- 原生 Apple Clang 21；Emscripten 6.0.12；Node.js 25.9.0。
- 两端 Release `-O3`，关闭浮点乘加收缩，不开启 `fast-math`。
- 真实浏览器 smoke test：Chromium 155，通过。

| 内容 | 原始大小 | 传输压缩大小 |
| --- | ---: | ---: |
| 实验 `.wasm` | 3,643,732 B（3.47 MiB） | Brotli 2,771,681 B（2.64 MiB） |
| Emscripten JS 加载器 | 77,221 B | gzip 19,696 B |
| 现有 DE442 全覆盖 11 个 OPM2 文件 | 3,277,000 B（3.13 MiB） | gzip 合并统计 3,137,835 B |

数据没有嵌入 Wasm，首次不加载 OPM2 也能用内置半解析模型。数据档复用现有
DE442 文件，没有另行生成 1900～2100 裁剪包，也没有包含小行星、恒星或 COB 包。
这不是导出全部 C ABI 后的最终 SDK 大小；链接器仅保留本实验调用可达的代码。

初始 Wasm 线性内存为 64 MiB，可增长；这不是下载体积，也不是整个浏览器的
实际内存占用。Base64 会增加约三分之一的文本长度，并产生解码临时内存，适合作为
可选输入，不建议把整套数据默认转成 Base64 塞进 JS 源码。

## 精度与错误处理

以下是同一内核、同一配置的 Wasm 与原生差异，**不是重新评估对 DE442 的绝对
天文精度**，也不表示所有日期和功能都已经验证。

| 对照项目 | 已测最大差异 |
| --- | ---: |
| 半解析位置：240 次成功计算的黄经/黄纬 | 1.60 × 10⁻¹¹ 角秒 |
| OPM2 位置：180 次成功计算的黄经/黄纬 | 1.44 × 10⁻¹¹ 角秒 |
| 位置分量/距离（两档合计） | 2.14 × 10⁻¹⁴ AU |
| 夏至、日食食甚及接触时刻（两档合计） | 1.66 × 10⁻⁸ 秒 |
| OPM2 接缝成功样本的 XYZ 分量 | 3.56 × 10⁻¹⁵ AU |

覆盖 10 个目标、8 个历元、默认视位置/速度/几何 XYZ 三种模式。行星使用系统
质心 ID，不把它们冒充物理中心的性能结果。OPM2-only 档另有 60 次覆盖外拒绝，
两端状态一致，没有回退半解析。接缝共 165 个样本，其中 56 个覆盖/组成路线边界
拒绝也一致；不能把这些拒绝算成成功求值。

三个农历日期逐字段一致：2025 正月初一、2033 闰十一月初一、2033 普通十二月
初一。事件测试包含 2026 夏至与 2024-04-08 全球日全食、食甚位置和五个接触时刻。
64 位 CallResult 通过 BigInt 传递，失败状态和低 32 位全部标记均可保留；损坏数据、
非法文件名、非法 Base64 以及重复加载均验证为拒绝。

浏览器运行了同一组位置、农历、夏至和日食计算；保存报告中的位置输出与 Node
Wasm 一致。接缝、完整原生精度对照和主性能统计由 Node 驱动执行。现有原生
`c_api`、`opm2_staged_data`、`chinese_calendar` 三项回归测试也通过。

## 性能

下面是预热后重复五次的中位数。位置每次 2,000 个历元、保留同一 ctx，依次调用
普通单目标 C ABI，不用 batch；十目标统计是每个天体的平均耗时。默认视位置，
无 SPEED。单目标是太阳，十目标是太阳、月球与八个行星系统质心，不宜把两行
差异简单归因于缓存。测量不包含网络下载，也不是跨浏览器性能保证。

| 场景 | 原生 | Wasm / Node | Wasm / 原生 |
| --- | ---: | ---: | ---: |
| DE442 OPM2：单目标视位置 | 2.10 µs | 5.69 µs | 2.71× |
| DE442 OPM2：连续十目标视位置 | 2.75 µs/天体 | 7.96 µs/天体 | 2.89× |
| DE442 OPM2：下一次全球日食，含接触时刻 | 0.351 ms | 1.044 ms | 2.97× |
| 半解析：单目标视位置 | 4.60 µs | 18.32 µs | 3.98× |
| 半解析：连续十目标视位置 | 20.96 µs/天体 | 74.55 µs/天体 | 3.56× |
| 半解析：下一次全球日食，含接触时刻 | 4.620 ms | 11.873 ms | 2.57× |

另测 JS → Wasm 调用、状态解包并复制三个结果，OPM2 太阳约 6 µs/次。
Chromium smoke test 的同档单目标约 5.6 µs、十目标约 8.1 µs/天体，但该浏览器
计时只跑一轮 500 历元，不与上表五次中位数混为同一统计口径。

Node 中预先读入 `.wasm` 后的实例化约 5～7 ms；本地浏览器页约 10 ms。
不包含公网下载，不能称为用户首次打开页面的总加载时间。

## 限制与下一步

本轮没有接入 Dart、Worker、并发、恒星、八字/紫微、自定义回调或完整时间尺度
接口，也没有验证 Safari、移动浏览器、Multi-GB SPK。Emscripten 的共享库与 miniz
大文件 I/O 警告尚不能据此宣布生产平台兼容；本实验使用静态链接和小型 OPM2。

下一步建议先把 Wasm 导出、数据加载与 ctx 生命周期收敛成稳定后端，再接 Dart
条件导入。保留 OPM2 二进制数据按需加载，也可从 Base64 字符串解码后加载。

复现命令见 [README.md](README.md)。完整本机报告保存在忽略的
`build-wasm/results.json`、`build-wasm/summary.json` 和
`build-wasm/browser-results.json`，不会混入发行包。
